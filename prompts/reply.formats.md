# MedPrism model edit proposal format

The language model proposes **what to change**. The runtime owns deterministic metadata such as SHA-256 hashes, project revisions, patch IDs, exact selection ranges, verified bibliography serialization, and compile job IDs.

## Hard rules

- Never append replacement prose to the end of a `.tex` file.
- Existing text must use `replace_text` with text copied exactly from the supplied source context.
- Insertions must use `insert_before` or `insert_after` with a unique anchor.
- For selection-scoped editing, use exactly the supplied selected text as `oldText`.
- Never output `baseSha256`, `projectRevision`, or a complete runtime `PatchSet`.
- Never emit `bib_add` from a writing/polish model step. Citation metadata and BibTeX are produced by the trusted citation workflow.
- If the target cannot be located safely, return an explanation without `patchProposal`.

## JSON envelope

```json
{
  "content": "Short explanation for the user.",
  "patchProposal": {
    "schemaVersion": "1",
    "summary": "Short edit label",
    "operations": [
      {
        "op": "replace_text",
        "path": "main.tex",
        "oldText": "exact text copied from context",
        "newText": "replacement text"
      }
    ]
  }
}
```

`path` may be omitted when the runtime supplied one active file. The runtime validates the path and attaches the current file hash and project revision.

## Allowed model operations

| Operation | Use |
|---|---|
| `replace_text` | Modify existing text |
| `insert_before` | Insert before one unique anchor |
| `insert_after` | Insert after one unique anchor |

The following are runtime-only and must not be generated by the model:

- `bib_add`
- `baseSha256`
- `projectRevision`
- `range`
- `mustNotExist`
- verified DOI/PMID metadata

Legacy `suggestion` fences and model-supplied full `PatchSet` objects are display-only and cannot be kept.
